# Schedule 开发日志

# 第零阶段 · 从 Planly 起步（v1.0 – v1.4）

> **说明**：v1.5.0 之前没有留下版本说明文档，具体每个版本号做了什么已经无法逐条还原。
> 下面分两部分写：**能从代码和数据结构里确认的**，和**依据迁移函数反推的**。分不清的地方我直说。

## v1.0.0 起点：把 Planly 变成一台安卓 App

原始项目 [Planly](https://github.com/danil-kokorev/planly) 是一个俄语/英语的网页日程应用，设计核心不是「待办清单」，而是「任务 + 精力」——一天 100 分，做完一件事扣一点。这个思路整条线都保留了下来。

第一版做的事：

**1. 安卓壳**
`MainActivity` 里放一个 WebView，`loadUrl("https://app.local/")`，所有 `shouldInterceptRequest` 都从 `assets/www/` 里取文件。这相当于自己实现了一遍 WebViewAssetLoader，比 `file://` 安全（没有同源绕过问题），也让后面所有「本地单文件网页」的做法成立。

**2. JS 桥**
`@JavascriptInterface` 暴露一组原生能力给网页：通知、闹钟、备份文件读写、组件的课表推送。前端 `nativeApp()` 判断在不在壳里，在浏览器里打开也能用（只是没有通知和组件）。

**3. 中文界面**
原项目是俄语为主、英语次之。第一版把界面文案都换成中文，但**没有做双语切换** —— 那时候直接把字符串写死在模板里。这个决定在 v1.9.23 付出代价：要做英文界面时，得把几百处硬编码逐个抽成字典（见后面的 v1.9.37、v1.9.61）。

**4. 打包链**
不用 Gradle，手写 `aapt2 → javac → d8 → zipalign → apksigner`。原因很实际：沙箱里装 Gradle 和 AGP 太重、太慢，而项目只有一个 Activity、十个 Java 文件，手动打包完全够用，一次构建十几秒。

**5. 数据**
全部存 `localStorage`（键 `planly.v1`），一个 JSON。`S` 对象就是整个数据库：

```js
S = { tasks, folders, notes, series, courses, moves, settings, del, log, settingsUpd, date, view }
```

`del`（删除标记）、`log`（每天每件事的完成记录）、`settingsUpd`（设置最后修改时间）这三个字段，是为原项目的**多设备合并**设计的 —— 同步时要判断「这条是新删的还是对方新加的」。后来同步没接服务器（v1.9.16 整块隐藏），但这套字段留了下来，正好给完成率统计和撤销用。

## 起点就带着的东西（从代码能确认）

这些在 v1.5 之前就已经存在，代码里能看到它们的初始形态：

| 功能 | 代码里的痕迹 |
|---|---|
| **精力系统** | 一天 100 分，每件事按「时长 + 优先级」算消耗；耗尽时显示 `计划 −N` |
| **六档状态** | 摆烂 / 轻松 / 还行 / 有点鸭梨 / 鸭梨好大 / 累趴，按剩余精力分档 |
| **猫** | 精力满 100 趴着睡，低于 45 趴下，其余坐着 |
| **时间轴** | `mode:'scale'`，`hour:64`（每小时 64px）、`dayStart:7`、`dayEnd:23`、`snap:5`（网格 5 分钟） |
| **优先级四档** | `PRI` 数组：低（灰）/ 中（主题色）/ 高（橙）/ 紧急（红），`URGENT=3` |
| **文件夹** | `S.folders`，任务挂 `folder` 字段 |
| **笔记** | `S.notes`，独立一页，可存可删 |
| **归档** | 完成的任务进归档，`KEEP_DAYS=14` 后清理 |
| **主题** | 浅色 / 深色 / 跟随系统 + 7 种强调色（绿蓝靛紫粉青石墨） |
| **折叠记忆** | `foldFixed`、`foldExtra`、`foldTlFixed`、`foldTlPlain`、`foldDue` 五个布尔值，分别记各分组的折叠状态 |
| **自动快照** | 滚动快照（20 秒节流）+ 每日一份，出问题能从最近的状态恢复 |
| **备份导出/导入** | 导出成 JSON，可发到微信再导回来 |

还有一处**俄语残留**一直留到现在：`PRI` 和 `ACCENTS` 的名字是 `tr('Низкий')`、`tr('Зелёный')` 这种，走的是原项目的翻译表。功能没问题，只是看代码时容易愣一下。

## v1.1 – v1.4：反推的四类任务模型

下面这些是从 v1.5.0 的改动说明倒推出来的 —— v1.5.0 写的是「以前是四种（固定 / 普通 / 按周 / 截止），现在归成三大类」，说明**四类模型在 v1.5 之前就已经成型**。

四类各自的形态：

| 类型 | 特征 | 后来怎么变的 |
|---|---|---|
| **固定任务** | 每天固定时间（如每天 7:30 背单词），带 `dailyDays` 字段 | 并进「周期任务 · 每天」 |
| **普通任务** | 一次性，有时间或没时间 | 保留，仍是普通任务 |
| **按星期任务** | 每周指定几个星期几，**每周生成一条独立记录**（`series` + `seriesId`） | 这是最大的技术债：任务页会看到同一门课重复好几条，v1.8.5 才统一成一条 |
| **截止任务** | 只设 `due`，从今天一直列到那天 | 保留 |

「按星期任务每周生成实例」这个设计，是 v1.8.5 那次大迁移的根源 —— `migrateSeries()` 要把所有旧的 `seriesId` 实例合并成一条周期任务，还要把历次完成记录（`S.log[日期][实例id]`）搬到新任务名下，否则用户的历史打卡就没了。那个函数里这段代码就是干这个的：

```js
insts.forEach(function(ins){
  if(!S.log[ins.date] || !S.log[ins.date][ins.id]) return;
  S.log[ins.date][nt.id] = 1;        // 旧的完成记录挪到新任务名下
});
```

同一时期大概还陆续加了：截止任务的倒计时标签（今天 / 明天 / 还有 N 天）、文件夹筛选、优先级分组、日历页的月视图。**具体是哪个版本加的，已经查不到了** —— 那时还没有写版本说明的习惯，这也是后来每一版都追加说明的原因。

## 这一段留下的三个教训

1. **字符串硬编码**：中文直接写在模板里，做英文时全部重抽了一遍。教训是「文案从第一行就该走字典」，哪怕当时只有一种语言。
2. **每周生成实例**：任务记录由「时间规则」派生出来，看着直观，一旦要改规则就得迁移历史数据。后来所有周期任务都改成「一条记录 + 规则」，靠规则实时算今天是第几轮。
3. **不留记录**：v1.5 之前的东西现在只能靠代码反推。从 v1.9 开始每一版都写清楚改了什么、为什么，这个习惯就是从这次「想不起来」开始的。

# 第一阶段 · 任务模型（v1.5 – v1.8）

## v1.5.0 任务类型合并成三类

**为什么**：原来是四种（固定 / 普通 / 按周 / 截止），用户得记四个名字，还要判断自己这件事属于哪种。

**改成**：三大类，周期变成任务的一个属性：

| 大类 | 里面包含 |
|---|---|
| 周期任务 | 每天、每周一次、每月一次、以及按星期几重复的老任务 |
| 普通任务 | 一次性，有时间或没时间 |
| 截止任务 | 只设截止日期，之前做完就行 |

新建时只选「重复：不重复 / 每天 / 每周 / 每月」，不用记类型名。

**顺带定的规则**：每周 / 每月任务一律不占「今日计划精力」（和截止任务一样）；今天勾掉，本周期内不再出现，到下一个周期自动恢复成未完成。

**怎么确认的**：用三个任务（跑 3km 每周、720 分每月、背单词每天）手动跑了一遍时间线 —— 今天都在；勾掉跑 3km 后当天消失、明天也不出现；下周一自己回来；720 分下月 1 号回来。

## v1.5.2 周期任务分组

**为什么**：周期任务一多，靠卡片副标题判断「这条是每天还是每周」太累。

**改成**：标题右侧直接显示分布 `每天 3 · 每周 2 · 每月 2`；组内按每天 / 每周 / 每月分三小节，左侧彩色竖条区分（绿=每天、蓝=每周、琥珀=每月）；只有一类时自动不显示小节，少一层嵌套。

## v1.6.0 周期任务规则定型

| 选择 | 还要选什么 | 显示规则 |
|---|---|---|
| 每天 | 不用选 | 每天都出现，勾掉当天消失，第二天回来 |
| 每周 | 周几（可多选，也可不选） | 选了周三：周一二不出现，周三起出现，做完本周期消失 |
| 每月 | 几号（1–31，单选） | 选了 20 号：20 号前不出现，20 号起出现，做完本月消失 |

不选周几 / 几号 = 不限日子，这一周期内每天都列着，做完就消失（「每周跑 3 公里」就是这种）。

**注意**：这一版周期任务还不进时间轴 —— 选了重复会自动把任务切成「无时间」。

## v1.7.0 带时间的周期任务

**为什么**：v1.6 的规则让「每周四 18:40 街舞培训」这种带固定时间的周期任务没法用。

**改成**：同一个任务可以既是周期、又有具体时段。选了重复以后日期行自动隐藏（哪天由规则决定），开始时间和时长照常填；不想要时间就打开「无时间」开关退回列表。

带时间的周期任务会自动登记到点提醒；精力按当天是否真的排了来算，不带时间的不算。

## v1.8.0 任务页成型

- 周期任务永远留在清单里：今天勾掉，任务页照样能看到（带删除线表示今天这份已完成），明天变回待办
- 普通任务按优先级分四组（紧急/高/中/低）、周期任务按每天/每周/每月分小节，点标题收起，折叠状态记住
- 筛选说明改成直白的话：「周期任务：每天 / 每周 / 每月」「截止任务：只设截止时间，截止时间之前完成即可」

## v1.8.2 四个小改进

- **笔记页有了保存按钮**（顶栏最右，绿色），点一下保存不退出
- **日历每天按状态上色**：日期圆圈填实色，灰=摆烂、绿=轻松/还行、橙=有点鸭梨、粉=累趴；只看今天及以前，未来不上色，日历底部有图例

## v1.8.4 卡片编辑与周期任务修正

- 三个页面的卡片，垃圾桶旁边加了铅笔按钮。点铅笔才编辑，点卡片别处不再误触。归档页不加
- 带具体时间的周期任务左侧加蓝色竖条，一眼和普通周期任务区分
- **修「周三显示周四任务」**：带时间的周期任务只在设定的那天出现
- 任务页补全时间信息：「1 小时 · 社团」→「每周 周四 · 18:40 · 1 小时」
- 任务页新增「全部任务」筛选，三类混排按优先级排

## v1.8.5 周期任务统一 + 归档可删

**为什么**：老「按星期排」的任务每周会生成一条独立记录，任务页里「书协培训」重复出现好几条。

**改成**：升级后第一次打开自动合并成一条「每周 周二 18:40 书协培训」，历史完成记录一并搬过去。每条周期任务的颜色各不相同（左侧竖条），今天 / 日程 / 任务三页一致。

归档页每张卡片右边加垃圾桶，可单条删，删前确认。

## v1.8.7 打勾统一在今天页

- 只有「今天」页的卡片能打勾，日程页和任务页的勾选框移除（避免误判）
- 日程页时间轴模式只显示时间点，不再在下面重复堆卡片
- 日程页列表模式显示这一天全部任务（周期 / 普通 / 截止三组）

## v1.8.8 补记 / 折叠 / 删除

- 日程列表模式的「普通任务」也能折叠了

## v1.8.9 常见疑问

今天页右上角（齿轮左边）加了问号按钮，8 组 35 条：精力怎么算 / 任务与周期 / 打勾与记录 / 提醒 / 数据 / 界面。

**这一版定下了一个模式**：所有「怎么用」的说明都进这里，界面本身不再堆解释文字。后面 v1.9.43 的设置页瘦身、v1.9.48 的小组件说明，都是这个思路的延续。

## v1.8.10 完成率改成实时算

**为什么**：以前用的是打开 App 那一刻的快照，没开过的日子就没有记录（柱子显示「–」），做完任务也不一定及时更新。

**改成**：`完成率 = 那天做完的 ÷ 那天安排的事`，每天现算。

分母包含：每天任务、那天该出现的每周/每月任务、日期落在那天的普通任务、当天的截止任务。

**关键细节**：做完就从列表消失的周期任务，依然算在当天分母里 —— 否则做完反而把分母变小，数字会偏高。没打开过 App 的日子也能算出真实值。

## v1.8.11 完成情况看的是选中那天

以前不管看哪天，详情面板都只显示今天的数字。改成跟着选中的日期走。

# 第二阶段 · 课表与外壳（v1.9.0 – v1.9.36）

## v1.9.0 课表（这一版是整个 App 的转折点）

**为什么**：日程应用不知道你什么时候有课，排出来的时间就是假的。

**怎么做的**：课程直接画在日程页的时间轴上，和任务同屏 —— 左上角标节次、虚线浅底。课程是背景，任务是你要做的事，一眼分开。

**课程不算任务**：不能打勾、不占精力、不进任务页、不影响完成率。

三步用起来：

1. 设置 → 课表 → 导入课表：选教务系统导出的 Excel（要含「上课明细」那张表），解析出预览，确认无误再导入。没有 Excel 可以先把 PDF 交给 AI 转一下
2. 设置 → 课表 → 开学第一周：填第 1 周周一的日期（如 2026-09-07），填了才算得出「今天是第几周」
3. 设置 → 课表 → 节次时间：默认是广西大学作息，其他学校自己改，留空表示那节不排课

**调课**：点时间轴上的课程块 →「停这一次」或「改时间/地点」，只影响那一天。

## v1.9.7 / v1.9.8 主题、点击判定、FAQ

- 右上角改成太阳 / 月亮切换，切换时两个图标交叉旋转淡入淡出，底色和文字色一起渐变
- **时间轴点卡片**：以前要「按住不动」才打得开，是判定机制的问题。改成松手走标准点击，拖拽过才忽略
- 常见疑问补两组共 9 条（课表 5 条、时间轴 4 条），总数到 35 条；顶部加搜索框，边打边过滤，搜到自动滚到第一条
- 右下角圆形 ↑ 按钮：往下滑就出现，点一下回到最上面
- **新用户使用说明**：首次打开自动生成一条「使用说明」笔记，八小节

## v1.9.9 切到时间轴停在最上面

以前从「列表」切回「时间轴」会自动滚到当天第一个任务（下午有事就跳到下午），改成一律停在「一天开始」那个点。

## v1.9.10 时间轴记住上次位置

按日期分别记住滚动位置：今天停在 20:00，切走再回来还是 20:00。

顺带修掉一个怪现象：以前停在最上头时切出去再进来会自己跑到下面（旧逻辑会去找「屏幕里有没有任务块」，找不到就滚到第一个任务）；现在不找任务了，只看历史位置。

## v1.9.12 时间轴左侧时间不再叠字

**问题**：两个安排紧挨着时（07:50 结束、08:00 开始），边界时间只有 11px 间距，字压在一起。

**改法**：挨太近的一组时间上下让开，间距统一撑到 17px，各自仍贴着自己块的上/下沿；让开时这组时间缩一号字（11.5 → 9.5px）；整点刻度如果正好和块边时间撞上就自动隐藏；很短的小块（十几分钟）只标开始时间。

## v1.9.13 左侧刻度回归纯刻度，起止时间挪进卡片

- 最左列只有整点刻度，不再显示块起止时间，彻底不会有叠字
- 每张卡片最左端显示这件事的时间：开始在上、结束在下，分别贴着卡片上/下沿，中间一条淡竖线分隔
- 卡片太矮（< 50px，约 45 分钟）只显示开始时间，时长写右边
- 并排的窄卡片时间列会缩窄、字号小一号

## v1.9.14 周期任务在任务页不再被划掉

**问题**：周期任务的「完成」只属于当前这一轮，但任务页套用了普通任务的完成样式，一划掉看着像永久做完了。

**改法**：标题不划线不变灰，右边挂小绿标「今天已完成 / 本周已完成 / 本月已完成」，下一轮开始标记自己消失。顺带修掉周期任务被归档的问题。

## v1.9.15 / v1.9.16 同步说明与隐藏

## v1.9.39 修「提醒不准时 / 打开 App 才响」

**现象**：任务 9:30、提前 10 分钟提醒，人一直没动 App，9:21 打开才收到。

**两个原因**：

1. **精确闹钟权限没拿到**。Android 14 起，`SCHEDULE_EXACT_ALARM` 对 targetSdk ≥ 33 的新装应用默认拒绝。没有它系统只给「不精确闹钟」—— 可以在合适的时候才投递，待机、省电模式下拖几十分钟很常见，直到设备被唤醒（你打开 App）才一起发出来。
   **修法**：清单里加 `USE_EXACT_ALARM`（Android 13 起这类应用安装即授予，不需要用户点）。

2. **App 开着的时候没走系统闹钟**。前台检查器只在「提醒时间的 3 分钟内」补发，超过就当错过了。窗口放宽到 15 分钟，闹钟万一没响，打开 App 也能看到。

**顺手做的**：
- 登记范围从 3 天扩到 7 天
- 设置 → 提醒新增「闹钟精度」一行，显示「精确 / 不精确 · 点此开启」
- 新增「30 秒后叫醒我（锁屏也能测）」—— 真走系统闹钟，锁屏 30 秒后该响
- 闹钟失败时不再把待取消列表清空

## v1.9.41 找到「测试通知点了没反应」的真正原因

**不是权限问题，是一个字母打错了。**

按钮在页面里的 id 是 `sTestNoti`，JS 里绑的是 `#sTestNotify`（末尾多一个 y）。查询不到元素，`if(tnb)` 直接跳过 —— **这个按钮从头到尾就没绑上任何东西**，所以点了连 toast 都没有。

这也解释了为什么 30 秒闹钟能响、这条不能：闹钟走的是完全不同的链路（AlarmManager → 广播 → 通知）。

**修法**：改 id，并且给打包流程加了一道检查 —— `check_ids.py`，JS 里绑定的 `#id` 如果在 HTML 里找不到，打包时报 `missing ids: [...]`。这个脚本现在是 `build_apk.sh` 的第 0 步。

**这一版还会看到的变化**：

## v1.9.57 找到真凶：尺寸读错了

**为什么之前怎么调都不对**

画布尺寸一直用 `OPTION_APPWIDGET_MIN_HEIGHT` 读。**vivo 在拉大组件时只更新 MAX，MIN 还停在初始值（300dp）**。于是按 300dp 画好的图被 fitXY 硬拉到 420dp 显示 —— 纵向拉伸 1.4 倍，卡片变细长、字变形、4×6 里第四行内容根本出不来。

诊断时看到过 `1088×2000` 这种离谱的尺寸（取 `max(min,max)` 之后），说明各家 launcher 的上报值完全不可信。

**这一版的做法**：不再猜绝对尺寸，改按**宽高比**判定 4×4 / 4×5 / 4×6（比例不受绝对值影响），每种用固定画布：

| 档位 | 画布 | 每格 |
|---|---|---|
| 4×4 | 250×300dp | 课名 + 地点 |
| 4×5 | 250×370dp | 课名 + 地点 + 节次 |
| 4×6 | 250×440dp | 课名 + 地点 + 节次 + 开始时间 |

画布按 1.7 倍密度渲染，被桌面缩放后不糊。卡片高度封顶在列宽的 2.1 倍。

**顺带**：设置里点「组件状态」能弹出 `宽x高 比例 → 档位`，是桌面实际报上来的值，排查全靠它。

## 2.0.1 检查更新

**方案定的很晚**：从 v1.9.44 开始就一直"留着位置以后做"，`NET_ON` 开关关掉了所有联网请求，包括原项目那个指向 `https://app.local/version.txt` 的假检查。

**这一版真的做了**：

1. **请求交给原生发**。WebView 里 `fetch` 跨域会被 CORS 拦（页面在 `app.local`，目标在 jsDelivr），所以用 `HttpURLConnection` 在 Java 侧请求，结果通过 `evaluateJavascript` 回调成 `window.__onUpdate(json)`。原生请求还有个附带好处：不受前端 `NET_ON` 开关影响，同步仍然是关的，只有版本检查这一条通道。

2. **比 `code` 不比字符串**。`2.0.10` 和 `2.0.9` 按字符串比会得出错误结果，所以版本文件里带一个数字 `code`，和 `versionCode` 直接比较。

3. **两档触发**：启动 5 秒后静默查一次（`localStorage` 记时间，24 小时内不重复），设置页「检查更新」可以手动查。静默模式只弹一次 toast（按版本号去重），手动模式打开完整弹窗。

4. **下载走系统浏览器**。`openUrl()` 用 `ACTION_VIEW` 把链接交给浏览器，App 自己不下载、不需要 `REQUEST_INSTALL_PACKAGES` 权限。用户装的时候系统会校验签名 —— 签名不同就装不上，这是防假包的最后一道。

5. **顺手修了个旧 bug**：`appVersion()` 一直返回硬编码的 `"1.9.35"`，改成读 `PackageManager` 的真实 versionName。

**验证**：用 Playwright 直接调 `window.__onUpdate` 模拟原生回调 —— 有新版弹窗正常（版本号、当前版本、更新内容、按钮齐全）、旧版本不弹、设置页那行显示 `v2.0.1 ›`。

**部署时要改的两处地址**（改仓库名时）：
- `MainActivity.java` 的 `UPDATE_URL`（默认 `cdn.jsdelivr.net/gh/<user>/<repo>@main/version.json`）
- 仓库根目录 `version.json` 里的 `url`

## 2.0.2 课表导入重写：能认各省教务系统的网格课表

**为什么改**

发到朋友圈第一天就翻车。两位同学把教务系统导出的 Excel 导进来，屏幕上是一条条橙字：

```
第 1 行：没认出星期几 → 课程表 · 第2周
第 2 行：没认出星期几 → 节次 / 时间 周一 10/5 周二 10/6
第 3 行：没认出星期几 → 第1节 08:00 09:40 数学 智能大楼
```

一条课都没进去。

把两份文件拆开看，才发现自己从头到尾只在支持一种格式。当初写导入时脑子里想的是「一行一门课」的明细表：

```
课程名称 | 星期 | 节次 | 周次 | 地点 | 教师
高等数学 | 星期一 | 3-4节 | 3-18周 | 东10A-104 | 甘小霞
```

而教务系统导出的是另一种东西 —— 整张表是一周的样子，星期横在表头，节次竖在左边：

```
节次 / 时间        周一    周二    周三
第1节 08:00-09:40  数学    思修    （无课）
第2节 10:00-11:40  电工    工程力学 电工
```

**这种表的每一行都没有「星期」这两个字**。旧的解析器逐行找星期，找不到就报错 —— 于是每一行都报错，一条都不剩。

更要紧的是：这个格式不是特例，是主流。学生个人课表基本都是这样导出来的。也就是说 2.0.1 对绝大多数同学根本不可用，而错误提示长得像「文件坏了」，没人会想到是软件只认一种格式。

**两份文件的差异比想象中大**

同样都是网格表，两位同学的表几乎没有共同点：

| | A（xlsx） | B（xls） |
|---|---|---|
| 表头写法 | `周一` + 换行 + `10/5` | `星期一` |
| 节次写法 | `第1节` + `08:00` + `09:40` 三行 | 没有节次行，节次在格子里：`(1-2节)` |
| 行标签 | A 列 | A 列写时段（上午/下午/晚上），B 列写 `一二三四五` |
| 格子内容 | `数学 / 智能大楼 / A302 / 侯志强` 四行 | `管理学原理/(1-2节)7-18周/西校区 教1212(西)/孔玲2/...` 斜杠串 |
| 周次 | 没有 | 有，还带单双周 |
| 一天的节数 | 5 大节（每节 100 分钟） | 10 小节 |

所以不能写两个 if，得写一个能自己看表结构的解析器。

**改了什么**

新增 `parseGridSchedule()`，思路是「先认表头，再按列归属」：

1. **找表头行** —— 扫前 25 行，数每行有几个格子长得像星期，取最多的那行。要求 ≥2 个，避免把数据行误当表头。
2. **建列映射** —— 表头第 3 格是「周二」，那这一整列都是周二。**不再假设列偏移**：A 的课从第 2 列开始，B 从第 3 列开始，各自算各自的。
3. **转置兜底** —— 表头找不到星期，就回头看第一列是不是星期（有些学校表是横过来的）。
4. **认节次** —— 先看行标签，`第1节` / `1-2节` / `08:00-09:40` 都行；行标签没有就去格子里找 `(3-4节)`。
5. **拆格子** —— 一个格子可能塞着课名、教室、老师、周次，按四种写法分别处理：
   - 有 `地点：` `教师：` `周次：` 标签 → 按标签取
   - 有斜杠 → `课名/(1-2节)7-18周/地点/教师/教学班/人数/学分` 按段拆
   - 多行 → 第一行课名，最后一行像人名的当老师，中间全算教室（`智能大楼` + `A302` 拼成 `智能大楼 A302`，不拆成两个地方）
   - 单行 → 整行当课名
6. **认不出的要说话** —— 每一行、每一格认不出都记一条，预览页照旧列出来，不静默丢。

**顺手解决的三件事**

**作息时间**。A 的一天是 5 节、每节 100 分钟，跟默认的广西大学 13 小时制完全是两套。所以解析时把行标签里的 `08:00-09:40` 记下来，导入时问一句「按课表更新节次时间」，勾上就写进设置。B 的表里没有时间，就不问，沿用现有的。

**开学日期**。B 的表尾写着「本学期2026-08-31正式上课…共20周」，直接读出来。A 的表头写着「第2周 · 周一 10/5」，反推第一周周一 = 10/5 − 7 天 = 9/28。两个都能自动填，导入时也是勾选确认。

这一条很关键：`termStart` 没设的话 `coursesOn()` 直接返回空数组，课表一片空白，用户会以为导入失败。

**节次不够用**。原先考虑不周：先导入 A（作息改成 5 节），再导入 B（课程到第 10 节），第 6–10 节的课会因为 `periodOf()` 返回 null 而消失，而且不报错。现在的做法是导入后算一遍最大节次，超过了就补到够用（优先用默认作息，不够再按每节 45 分钟往后递推）。

**踩的四个坑**

1. **日期正则把学分当日期**。`/(\d{4})-(\d{1,2})-(\d{1,2})/` 在 `管理学原理-0001/80/4/52/3.0` 里匹配出了 `0001/80/4`，算出来的开学日期是 `0001-80-04`。改成 `20\d{2}` 开头，并且只在含「学期 / 开学 / 正式上课」的行里找，才算对。

2. **无课的节次没记进作息**。A 的第 5 节整行都是「（无课）」，代码先判断「这一行有没有课」，没课就 `continue`，于是第 5 节的 19:00–21:00 没被记录，作息只有 4 节。改成先记作息、再判断有没有课。

3. **表头行被判成数据行**。明细表的第一行是「课程名称 星期 节次…」，逐行解析时会报一条「没认出星期几」。加了一条表头特征判断（同时含「课程名称」和「星期/节次/教师」就跳过）。

4. **同一格里两门课没处理**。教务系统一般不会这么排，先不做，认不出会在预览里露出来。

**怎么确认的**

不看截图猜，五条路一起验：

1. **真实文件跑通**。两份文件在 Chromium 里用真正的 SheetJS 读（不是我另用 Python 转的 JSON），走 `sheetToRows → parseAnySheet`：A 认出 13 门课、B 认出 17 门课，**错误 0 条**。
2. **变体回归**。手工构造了 5 种：旧明细表、转置表（星期在左）、键值对表（`地点：`）、带标题行和周六的表头、单双周。全部认出，且**旧明细表格式没有退化**（这条最重要 —— 不能为了兼容新格式把原来能用的搞坏）。
3. **跨学校**。先导 A 再导 B：30 门课、作息补到 13 节，逐门检查 `periodOf(j1)/periodOf(j2)`，**对不上的一门都没有**。
4. **导入后真渲染**。点完确认导入，跳到 2026-11-16：A 显示数学 08:00–09:40、电工电子技术 10:00–11:40、体育 15:30–17:20；B 显示管理学原理 08:00–09:40、高等数学 14:30–16:05。时间点、教室、无重叠。
5. **语法与图标号**。`node --check` 三个内联脚本块全过；`check_ids.py` 通过。

**这一版真正的收获**

问题不在「少支持一种格式」，在于**我默认了用户的数据长什么样**。写导入的时候手里只有一份自己造的样例，就以为全世界的课表都长那样。

凡是「用户会拿各种来源的文件来喂」的功能，至少要拿三份真实的、来自不同来源的样本才能动手。这次是第一版发出去之后才收到样本，代价是一天的返工和两位同学装了个用不了的软件。

## 2.0.3 第三份课表：一格塞三门课、文字溢出、字段式写法

**为什么改**

2.0.2 发出去当天，第三位同学的课表（车辆2602）又导不进来。这份表跟前两份完全不是一个路子，把之前所有假设都推翻了。

**这份表长什么样**

节次是数字 1…11 竖在左边，星期横在上面，看着像前两份的同类。但打开格子一看：

```
高等数学(一
)(09A00010)★
(1-2节)5-17周/校区:主校区
/场地:11J2102/教师:韩雪/职
称:副教授/主辅讲:主讲/教
学班:高等数学(一)-0006/教
学班组成:车辆2602;土木
2601;土木2602;土木2603/课
程性质简介:专基/教学班人
数:125/最终容量:125/选课人
数:100/考核方式:考试/选课
备注:/授课方式:/课程学时
组成:理论:80/周学时:6/总学
时:84/学分:5.0
```

一格里塞了十项信息，还分两种写法混杂：斜杠分段，段内又是 `键:值`。更麻烦的是**课名自己带了换行**（`高等数学(一` 和 `)(09A00010)★` 是两行），而括号被拆在两边。

还有两件更狠的：

**一格多课**。周六第 1-2 节那格塞了三门课（线性代数第 5 周、高数第 6 周、英语第 7 周，调课排的），中间用空行隔开。

**文字溢出到下一格**。格子太窄，一行放不下的内容被导出软件硬切到了下面几行的空单元格里。比如 H3 的内容在 `周学时` 处断开，剩下的 `:4/总学时:48/学分:2.0` 跑到了 H5。

**三个 bug，一个比一个隐蔽**

1. **课名少个右括号**。`高等数学(一` 出来就是这个样子。
   原因：格子里有 `教师:韩雪`，命中了「键值对」分支（那个分支本来是给 `地点：xxx\n教师：xxx` 这种写法准备的），于是它按行切，第一行 `高等数学(一` 就被当成课名了 —— 而真正的右括号在第二行。
   改法：**斜杠分支优先于键值对分支**；同时键值对的标签必须落在行首（`(?:^|\n)`），不能是 `场地:11J2102/教师:韩雪` 这种半截。

2. **周次全错**，13 周的课被识别成「第 6 周」。
   原因：有个字段叫 `周学时:6`，代码为了兜底去从字段值里猜周次，`6` + `周` = 第 6 周。
   改法：删掉从字段值猜周次的逻辑。周次只从三点取：课名段里的 `(1-2节)5-17周`、独立的周次段、`周次:` 字段。

3. **凭空多出「4」「分:3.0」「1.0」这种课**。
   原因：文字溢出的续行被当成了独立的一行，`jt` 从行标签拿到了节次（比如第 2 节），内容 `:4/总学时:48/学分:2.0` 被当成一门课。
   改法：**先把所有「节次块」收集起来**，续行（这一行没有自己的时段/节次标签）归属到「上面第一个在相同列上有内容的块」。同时加一道兜底：课名是纯数字、或形如 `分:3.0` 的，算碎片，不进列表。

**顺手补的三种写法**

这三条是查资料时发现的，不是这三份文件里的，但都属于「同一格不同写法」：

- `高等数学 {第1-16周 张老师 A101` —— 强智系统 / WakeUp 项目的通用模板
- `高等数学@A101` —— `@` 后面是教室
- `英语A(张老师)(201教室)` —— 连续两个括号，前面是老师后面是教室（`板块`、`理论`、`实验` 这类词的括号不拆）

**怎么确认的**

1. **三份真实文件，SheetJS 真读**：
   - 第2周（xlsx）：13 门，0 错误，作息自动读出 5 节，开学日期反推 2026-09-28
   - 信管2601（xls）：17 门，0 错误，开学日期读出 2026-08-31
   - 车辆2602（xlsx）：38 门，0 错误，教室都是 `11J2102` 这种、老师是 `韩雪`、周次完整
2. **七个变体全部通过**：旧明细表、转置表、键值对、花括号、`@` 与括号教室、带标题行与周六、单双周。旧格式没有退化。
3. **连续导入三份**：累计 68 门课，逐门检查 `periodOf(j1)/periodOf(j2)`，节次对不上的 0 门。
4. **界面**：预览页 38 条整齐列出；导入后时间轴上高数落在 08:00–09:40、教室 11J2102。

**这次真正想明白的事**

前两版我一直在「补格式」，这次发现问题的形状变了：不是「格式不同」，是**同一个格子里混着两套写法，而且文字会被物理切断**。

只要解析器假设「一个单元格 = 一条完整信息」，就会一直踩。正确的假设是：**单元格是碎片，可能是半条、可能是三条、可能被切到隔壁行**。所以现在先用空行拆条、再按列拼碎片、最后才解析单条。

三份真实文件，三种完全不同的写法，样本还是太少。但至少现在遇到新写法，是「往里加一条规则」，不是「重写一遍」。

## 2.0.4 导不进去时的兜底：让 AI 帮忙转一道

**为什么改**

2.0.3 之后，三份真实课表都能导入了。但我很清楚一件事：**这个功能永远不可能穷举完所有的表格格式**。三份样本之外的学校还有多少种写法，不知道；下一次可能又是一份「一格塞五门课、周次写成 `{第1-16周(单)`、教室写在备注里」的表。

继续一条一条加规则，等于把用户的失败当成常态。

所以加了最后一道兜底：**导不进去的时候，让 AI 帮你转**。

**为什么不是「让用户自己改 Excel」**

这是最先想到的方案，也是最差的。理由很简单：

- 普通同学不会改 Excel，光「合并单元格怎么取消」就能卡住一半人
- 就算改了，改完还得存盘、再传回手机、再选一次文件
- 而且他不知道「改成什么样才对」—— 让他去理解「一行一门课、六列」这件事，等于把解析器的活丢给用户

**所以做成这样**

只在「一门课都没读出来」的时候，预览页下面出现一个区块：

```
文件格式没认出来？可以让 AI 帮你转一下

不用自己改表格。① 复制下面这段话　② 连同课表一起发给 AI
（豆包、元宝、DeepSeek 都行，文件或截图都可以）　③ 把它整理好的
内容粘回下面这一栏。

[ 复制这段话 ]

AI 整理好后，把结果粘在这里
┌──────────────────────────────┐
│ 高等数学|周一|第1-2节|5-17周|11J2102|韩雪 │
└──────────────────────────────┘
[ 解析并预览 ]
```

三个刻意的设计：

**1. 不打扰能用的人。** 只要读出哪怕一门课，这个区块就不出现。绝大多数人永远看不到它。

**2. 一步到底，不用回来找文件。** 用户是在导入面板里卡住的，所以粘贴框就放在原地 —— 不用退出去、不用再去点「手动粘贴」、不用重新选文件。AI 给了结果，直接粘、直接解析、直接导入。

**3. 不用「制表符」，用竖线。** 提示词里让 AI 输出 `课程|星期|节次|周次|地点|教师`。原因很实际：制表符在聊天框里经常被吃掉或者转成空格，竖线不会。而且解析器两种都认（`split(/\t|\s*\|\s*/)`），AI 万一输出制表符也不会坏。

**提示词本身**

```
我有一份大学课程表（文件和截图在下面），是教务系统导出的。请帮我整理成
一行一门课的文本，我要导入到手机 App 里。

每行一门课，用竖线 | 分成 6 列：
课程名称|星期|节次|周次|地点|教师

规则：
1. 星期写 周一 / 周二 / … / 周日
2. 节次写 第1-2节；只有一节就写 第5节
3. 周次写 1-16周；只有单周写 1-16周(单)，只有双周写 2-16周(双)；
   每周都上写 每周
4. 地点写楼名加房间号，如 11J2102；没有就留空
5. 教师没有就留空，空的那一列也要保留竖线
6. 标着「无课」的格子跳过，不要输出
7. 同一门课一周上几次就输出几行
8. 只输出这些行：不要表头，不要解释，不要代码块

例子：
高等数学|周一|第1-2节|5-17周|11J2102|韩雪
大学英语|周二|第3-4节|1-16周(单)|10J418|邵新光
体育|周四|第5节|每周||王冉
```

第 5 条（空列也保留竖线）和第 8 条（不要表头不要解释）是必须写的。少任何一条，AI 输出都会列错位或者多出废话行。

**顺手修了三个老毛病**

做这个功能时测「AI 返回的内容能不能粘回来」，发现粘不回来。查下去是三个更早就存在的问题：

1. **「手动粘贴」入口只认明细表**。它调的是 `parseCourseText`，不走网格解析。等于用户在别处整理好网格格式贴进来，照样失败。改成走 `parseAnySheet`。
2. **`第1-2节` 认不出**。旧正则要求节次是 `3-4节` 这种不带「第」的写法。加了 `第?`。
3. **`每周` 认不出**。只认带数字的周次，`每周` 既没有数字也不该报错，但会报「没认出周次」。现在单独识别，周次记为空数组（= 每周）。

这三个都是「只有自己造的测试数据能过」的典型。真实用户的输入永远比测试脏。

**怎么确认的**

不看文案顺不顺眼，走完全流程（Chromium + Playwright）：

1. **造一个肯定导不进去的文件**（一张学生信息登记表），选进去 → 预览页出现「没读到课程」+ AI 区块，复制按钮和粘贴框都在。
2. **读提示词**：`aiPrompt()` 输出完整，竖线格式，例子三行。
3. **模拟 AI 的回复**：带上「好的，我帮你整理好了：」这句开场白 + 四行数据，粘进框里点解析 → **识别到 4 条**，开场白被自动跳过，不打乱解析。
4. **点确认导入** → 课程数 4，时间轴上「体育 · 每周 · 周粉粉」（无地点）也正确。
5. **回归**：三份真实文件仍然 13 / 17 / 38 门、0 错误；七个变体（明细表 / 转置 / 键值对 / 花括号 / `@` 与括号 / 带标题与周六 / 单双周）全部通过，旧明细表没有退化。

**这一版的定位**

前几版一直在「把格式认全」，这一版是承认「认不全」。

区别在于：认不全的时候，用户不再是死路一条，而是有一条三步就能走通的路。而且这条路不要求他懂 Excel。

说实话，这条兜底路径如果经常被用到，说明解析器还不够好 —— 它应该是极少触发的安全网，不是常规入口。但它必须存在。

## 2.0.5 常见疑问补一条：把兜底路径放进能搜到的地方

**为什么改**

2.0.4 的「让 AI 帮你转」藏在导入面板里 —— 得先进设置、点导入、选完文件、发现没读出来，才会看到。可人遇到问题时的第一反应是去「常见疑问」搜，不是去点「导入」。

一个功能如果只存在于用户已经走到那一步的地方，等于半个不存在。

**改了什么**

常见疑问的「课表」分组里，在「怎么导入课表？」后面加了一条，中英各一份：

- 中文：「课表导不进去怎么办？」
- 英文：「The timetable will not import - what do I do?」

内容分三层，从最可能的原因往下写：

1. 先给信心：教务系统导出的两种都认，一格混着各种信息、一格塞多门课、文字被切到下一行，都能拼回来
2. 一门课都没读出来时，导入页面会出现 AI 兜底，三步走
3. 兜底也失败还有「手动粘贴」，并直接写出列格式 `课程名|星期|节次|周次|地点|教师`

第一句特意写成「先看文件对不对」，因为最常见的失败其实是「用户导的不是课表」—— 比如导了张学生信息表。

**顺手补的英文说明**

英文界面的提示词示例里，`Advanced Maths|周一|第1-2节|5-17周|11J2102|Han Xue` 这种中英混排看着别扭，但星期 / 节次 / 周次三列**必须**是中文 —— 解析器读的就是这个格式，和界面语言无关。

所以在英文提示词的规则前面加了一句：

> Note: the weekday / period / weeks columns stay in Chinese — that is the format the app parses, it is not a display language.

不解释这一句，英文用户会以为 App 翻译没做完。

**设置页没动**

加功能最容易犯的错就是往设置里堆开关。这次核对了一遍：课表区块还是 6 行 —— 在时间轴显示课程 / 开学第一周 / 已导入课程 / 导入课表 / 节次时间 / 清空课程。新东西只在导入面板里出现，设置页一个字没加。

**怎么确认的**

- 中文 FAQ 共 41 条，搜「导不进」命中 1 条，就是新加的那条
- 英文 FAQ 也是 41 条，和中文一一对应；搜 `import` 命中 4 条（导入、导不进、小组件课表、开学第一周）
- 英文界面下 AI 区块文案、提示词首行、说明句都正常
- 设置页中英各 6 行，长说明只有两行（开学第一周、桌面小组件），其余是一行说明或没有

## 2.0.6 小组件不翻周，和一份四段式课表

这一版修了两件互不相关的事，但都是用户报上来的。

### 一、小组件停在「第 10 周」

周一上午十点，桌面组件还写着「第 10 周 · 11/15 周日」。

看代码，是三处断链叠在一起，任何一处单独修好都不够：

**1. `updatePeriodMillis="0"`**
三个 widget_info 里都是 0，意思是「系统不用定期叫我」。于是组件只能靠自建闹钟唤醒来重绘。

**2. 自建闹钟用的是 `am.set()`**
非精确闹钟。Doze 模式下 `set()` 会被推迟到系统维护窗口，晚上深度睡眠时推到几个小时之后是常态。00:05 那一次翻周，很可能压根没在 00:05 发生。

**3. `BootReceiver` 只重排任务提醒，不管组件**
手机一重启，组件的每日闹钟就没了 —— 除非用户打开一次 App。这就是「有的人一直正常、有个人一直不翻」的原因：取决于他多久开一次 App。

三处一起改：

- `updatePeriodMillis` 改成 1800000（30 分钟），让系统兜底
- 闹钟换成 `setExactAndAllowWhileIdle(RTC_WAKEUP)`，能穿透 Doze；API 低于 23 用 `setExact`；再失败退回 `set()`
- 每天挂两个闹钟：00:05 和 12:05。一个漏了还有另一个
- `BootReceiver` 开机/应用更新后补排组件闹钟，并立刻重画一次
- `refreshAll()` 末尾顺手重排闹钟（幂等），这样任何一次刷新都会把链条接上，不会因为漏一次就永远断掉

装完新版，`MY_PACKAGE_REPLACED` 广播会立刻触发一次刷新，不用等第二天。

### 二、第四份课表：一格四段

同学发来的「学期理论课表」，四个 sheet：周课表 / 上课明细 / 课程一览 / 周次速查。周课表那格里是这个写法：

```
习近平新时代中国特色社会主义思想概论
（能物化生A08）
马娇 讲师
10-18周   汇学楼2幢304（多媒体阶梯）
```

四行分别是：课名、教学班代码、教师+职称、周次+教室。

旧的多行分支只会「第一行当课名，从后往前找像人名的当老师，剩下的全算地点」，结果是：

- 教室 = `（能物化生A08） 10-18周 汇学楼2幢304（多媒体阶梯）`
- 老师 = `马娇讲师`

能导进去，但难看，而且周次是靠整体兜底猜出来的。

重写这个分支，按这四段的形状拆：

1. 整行就是一个括号包着的短串（且不含楼/室/周）→ 教学班代码，丢掉
2. `姓名 + 空格 + 职称` → 只要姓名
3. 含 `N周` 的行 → 拿走周次，剩下的当教室
4. 其余累积成地点

两个坑：

- `（形策（一）22）` 是嵌套括号，`[^)）]` 匹配不进去。改成「整行以括号开头结尾、长度小于 26、不含楼室周」就判为教学班代码。
- `7、10、13、16周` 只有末尾带「周」，原来那个按段剥离周次的正则会留下 `7、10、13、`。改成「从行首删到第一个『周』字」。

顺手统一了教师名的处理：不管走哪条解析路径，末尾的「讲师 / 副教授 / 教授 / 助教 / 研究员 / 外聘…」都剥掉，交给 `normalizeCourse` 统一做。

### 三、多张表打平时优先「明细」

这份文件里「周课表」和「上课明细」都是 16 条。`上课明细` 是标准的一行一门课、带列头，比网格表可靠。加了一条：条数打平时，名字含「明细」的那张优先。

### 四、部分失败也给人留条路

原来 AI 兜底只在「一门课都没读出来」时出现。但如果一个表读出 2 门、漏掉 28 门，用户看到「识别到 2 条」加一堆橙字，多半以为「差不多能用」就直接导入了，结果是残的。

改成：**错误条数 ≥ max(3, 已识别门数)** 时也出现兜底区块，标题换成「有些课没读出来？也可以让 AI 整理一遍」。

阈值取 `max(3, 门数)` 而不是固定值，是为了两边都不误伤：40 门课错 3 条属于正常噪声，不该弹；2 门课错 3 条就是真的读残了。

### 怎么确认的

- 四份真实课表：13 / 17 / 38 / 16 门，全部 0 错误；第四份自动选中「上课明细」，教室是 `汇学楼2幢202（多媒体阶梯）`、老师是 `粟国康`
- 七大变体回归全过，旧明细表格式没退化
- 造了一份「2 门课 + 3 条错」的文件，兜底区块如期出现，标题是「有些课没读出来」
- 四份正常文件都不出现兜底区块（不该打扰人）

小组件那部分没法在沙箱里跑真机，只能保证编译通过、逻辑顺序对。真正的验证要看用户重装后第二天能不能自己翻周 —— 这是这一版唯一「交付即待验证」的东西。

## 2.0.7 版本号写死在页面里

**为什么改**

用户装了 2.0.6，打开设置，「检查更新」那一栏写的还是 **v2.0.1**。

**根因**

`index.html` 第 2610 行：

```js
var BUILD='2.0.1'; var VCODE=115;
```

六个版本以来，我每次只改 `AndroidManifest.xml` 的 versionCode / versionName，从来没有回头看这两行。网页里的版本号和安装包里的版本号，从 2.0.1 起就分家了。

**为什么这个比"显示错"严重**

`updPaint()` 判断有没有新版本的依据是：

```js
if(updLatest&&+updLatest.code>VCODE){ 显示「X 可更新」 }
```

页面以为自己是 115，实际装着 121。只要远端 `version.json` 的 code 大于 115，就会一直提示「有新版本」。**装了最新版的人，反而永远在被提示升级。**

**改了三处，逐层兜底**

1. **兜底值跟着发版走**：`BUILD='2.0.7'; VCODE=121`
2. **启动时从安装包读真实版本**：调用原生 `AndroidBridge.appVersion()` 和 `appVersionCode()`
   （Java 侧原来只有 `appVersion()`，补了一个返回 versionCode 的接口）
3. **打包脚本自动同步**：`build_apk.sh` 在编译前从 `AndroidManifest.xml` 提取版本号，`sed` 覆盖进 `assets/www/index.html`

第 3 条才是治本的。前两条治症状，第 3 条治「我下次还会忘」。

**顺手发现的一件事**

`MainActivity` 里 `appVersion()` 从 2.0.1 就写好了，而且在 2.0.1 的日志里我还专门写了「修复设置页显示的版本号不同步的问题」。

但这一版查下来，JS 里**一次都没调用过它**。接口写好了、没人接，等于没写。当时改的是别的地方（设置页底部读的是 `BUILD` 变量，那个变量才是硬编码的源头）。

这也解释了为什么 2.0.1 之后一直没人发现：`BUILD` 和真是的版本名在 2.0.1 那一版恰好一致，看起来是对的。等到 2.0.2 之后才逐渐错开。

**怎么确认的**

- 浏览器直接打开（没有原生桥）：`BUILD=2.0.7 / VCODE=121`，兜底值生效
- 注入一个假的 `AndroidBridge` 返回 `9.9.9 / 999`：页面读到 `9.9.9 / 999`，真实读取路径通
- 打的包里 `var BUILD=` 是 `2.0.7`，`aapt2 dump badging` 是 `versionCode='121' versionName='2.0.7'`，两边一致

**关于「检查更新」本身**

链路是通的（jsDelivr 返回 200，JSON 正常）。但有两个使用上的事实要记住：

1. **jsDelivr 对分支引用有缓存**，推完新的 `version.json`，可能要等几分钟（最坏几小时）才生效。刚推完就点检查，读到旧值，会显示「已是最新」——这种情况下无法区分是「真的最新」还是「读到缓存」。
2. 想主动验证「发现新版本」这条路径，最稳的办法是临时把 `version.json` 的 `code` 改成一个很大的数（比如 999）推上去，点检查，应该弹「v9.9.9 可更新」；验完再改回来。这样验证的是判断和弹窗，不依赖版本号是否刚好错开。

# 附录 A · 构建链路

不用 Gradle，手写脚本。一条命令出包：

```
aapt2 compile --dir res -o res.zip
aapt2 link -o app.unsigned.apk -I $PLATFORM --manifest AndroidManifest.xml \
    -R res.zip --java gen -A assets --min-sdk-version 21 --target-sdk-version 33
javac -encoding UTF-8 -source 8 -target 8 -bootclasspath $PLATFORM -d classes \
    gen/com/liu/dailycat/R.java src/com/liu/dailycat/*.java
d8 --lib $PLATFORM --min-api 21 --output dex classes/com/liu/dailycat/*.class
# 把 classes.dex 塞进 apk
zipalign -f 4 app.unsigned.apk app.aligned.apk
apksigner sign --ks $KS --ks-pass pass:$KS_PASS --out Schedule.apk app.aligned.apk
```

**第 0 步永远是 `check_ids.py`** —— 检查 HTML 里 `$('#xxx')` 绑定的 id 是否都存在。这条来自 v1.9.41 那个字母打错的事故。

# 附录 C · 反复出现的流程教训

**1. 补丁写对了 ≠ 生效**
出现过两次「assert 通过、脚本打印 ok，文件却没变」：
- 同一个 Python 脚本里先改了 `s`，后面又 `s = io.open(P).read()` 重读一遍，把前面的修改冲掉
- 改完忘了 `cp index.html app-src/assets/www/`，打出来的包还是旧的

现在固定流程：改 → grep 确认落盘 → 同步 assets → `check_ids.py` → 构建 → 报版本号。

**2. 大文件不能用 file_edit**
`index.html` 450KB，用 file_edit 会丢内容、错位，或者报成功但实际没改。一律改成「写 Python 脚本做精确字符串替换，每处 `assert s.count(o)==1`」，最后 `node --check` 验证语法。

**3. 视觉问题必须真渲染**
不靠脑补。组件用 `preview_widget2.py`（PIL 按真实 dp 复刻绘制逻辑），界面用 Chromium + Playwright 截图再局部放大看。`selftest_widget.py` 把「尺寸取值 → 判档 → 行高 → 内容分级」打成表格。

**4. 窄屏没测过等于没测**
v1.9.18–1.9.21 那四版返工，根因是一直在 800 宽视口里测，`.app` 有 `max-width:760` 兜着。之后所有布局都按 320 / 360 / 390 三个宽度各量一遍。

**5. 有些问题不是代码问题**
- 翻周按钮点不动 → launcher 不给子控件发点击
- 4×5 变 4×4 → launcher 用 `minHeight ÷ 单格高` 取整
- 读到 300dp 实际 420dp → launcher 只更新 MAX

遇到这类，第一件事是把平台给的原始值打印出来，而不是先改代码。

**6. 措辞要经得起时间**
启动页从「不联网」改成「单机运行」，是因为下一版就要加更新检查。写在界面上的承诺，等它变成假的再改，比一开始就写对更伤信任。
