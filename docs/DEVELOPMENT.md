# Schedule 开发日志

# 第零阶段 · 从 Planly 起步（v1.0 – v1.4）

> **说明**：v1.5.0 之前没有留下版本说明文档，具体每个版本号做了什么已经无法逐条还原。
> 下面分两部分写：**能从代码和数据结构里确认的**，和**依据迁移函数反推的**。分不清的地方我直说。

## v1.0.0 起点：把 Planly 变成一台安卓 App

原始项目 [Planly](https://github.com/danil-kokorev/planly) 是一个俄语/英语的网页日程应用，设计核心不是「待办清单」，而是「任务 + 精力」——一天 100 分，做完一件事扣一点。这个思路整条线都保留了下来。

第一版做的事：

**1. 安卓壳**
`MainActivity` 里放一个 WebView，`loadUrl("https://app.local/")`，所有 `shouldInterceptRequest` 都从 `assets/www/` 里取文件。这相当于自己实现了一遍 WebViewAssetLoader，比 `file://` 安全（没有同源绕过问题），也让后面所有「本地单文件网页」的做法成立。

**2. JS 桥**
`@JavascriptInterface` 暴露一组原生能力给网页：通知、闹钟、备份文件读写、组件的课表推送。前端 `nativeApp()` 判断在不在壳里，在浏览器里打开也能用（只是没有通知和组件）。

**3. 中文界面**
原项目是俄语为主、英语次之。第一版把界面文案都换成中文，但**没有做双语切换** —— 那时候直接把字符串写死在模板里。这个决定在 v1.9.23 付出代价：要做英文界面时，得把几百处硬编码逐个抽成字典（见后面的 v1.9.37、v1.9.61）。

**4. 打包链**
不用 Gradle，手写 `aapt2 → javac → d8 → zipalign → apksigner`。原因很实际：沙箱里装 Gradle 和 AGP 太重、太慢，而项目只有一个 Activity、十个 Java 文件，手动打包完全够用，一次构建十几秒。

**5. 数据**
全部存 `localStorage`（键 `planly.v1`），一个 JSON。`S` 对象就是整个数据库：

```js
S = { tasks, folders, notes, series, courses, moves, settings, del, log, settingsUpd, date, view }
```

`del`（删除标记）、`log`（每天每件事的完成记录）、`settingsUpd`（设置最后修改时间）这三个字段，是为原项目的**多设备合并**设计的 —— 同步时要判断「这条是新删的还是对方新加的」。后来同步没接服务器（v1.9.16 整块隐藏），但这套字段留了下来，正好给完成率统计和撤销用。

## 起点就带着的东西（从代码能确认）

这些在 v1.5 之前就已经存在，代码里能看到它们的初始形态：

| 功能 | 代码里的痕迹 |
|---|---|
| **精力系统** | 一天 100 分，每件事按「时长 + 优先级」算消耗；耗尽时显示 `计划 −N` |
| **六档状态** | 摆烂 / 轻松 / 还行 / 有点鸭梨 / 鸭梨好大 / 累趴，按剩余精力分档 |
| **猫** | 精力满 100 趴着睡，低于 45 趴下，其余坐着 |
| **时间轴** | `mode:'scale'`，`hour:64`（每小时 64px）、`dayStart:7`、`dayEnd:23`、`snap:5`（网格 5 分钟） |
| **优先级四档** | `PRI` 数组：低（灰）/ 中（主题色）/ 高（橙）/ 紧急（红），`URGENT=3` |
| **文件夹** | `S.folders`，任务挂 `folder` 字段 |
| **笔记** | `S.notes`，独立一页，可存可删 |
| **归档** | 完成的任务进归档，`KEEP_DAYS=14` 后清理 |
| **主题** | 浅色 / 深色 / 跟随系统 + 7 种强调色（绿蓝靛紫粉青石墨） |
| **折叠记忆** | `foldFixed`、`foldExtra`、`foldTlFixed`、`foldTlPlain`、`foldDue` 五个布尔值，分别记各分组的折叠状态 |
| **自动快照** | 滚动快照（20 秒节流）+ 每日一份，出问题能从最近的状态恢复 |
| **备份导出/导入** | 导出成 JSON，可发到微信再导回来 |

还有一处**俄语残留**一直留到现在：`PRI` 和 `ACCENTS` 的名字是 `tr('Низкий')`、`tr('Зелёный')` 这种，走的是原项目的翻译表。功能没问题，只是看代码时容易愣一下。

## v1.1 – v1.4：反推的四类任务模型

下面这些是从 v1.5.0 的改动说明倒推出来的 —— v1.5.0 写的是「以前是四种（固定 / 普通 / 按周 / 截止），现在归成三大类」，说明**四类模型在 v1.5 之前就已经成型**。

四类各自的形态：

| 类型 | 特征 | 后来怎么变的 |
|---|---|---|
| **固定任务** | 每天固定时间（如每天 7:30 背单词），带 `dailyDays` 字段 | 并进「周期任务 · 每天」 |
| **普通任务** | 一次性，有时间或没时间 | 保留，仍是普通任务 |
| **按星期任务** | 每周指定几个星期几，**每周生成一条独立记录**（`series` + `seriesId`） | 这是最大的技术债：任务页会看到同一门课重复好几条，v1.8.5 才统一成一条 |
| **截止任务** | 只设 `due`，从今天一直列到那天 | 保留 |

「按星期任务每周生成实例」这个设计，是 v1.8.5 那次大迁移的根源 —— `migrateSeries()` 要把所有旧的 `seriesId` 实例合并成一条周期任务，还要把历次完成记录（`S.log[日期][实例id]`）搬到新任务名下，否则用户的历史打卡就没了。那个函数里这段代码就是干这个的：

```js
insts.forEach(function(ins){
  if(!S.log[ins.date] || !S.log[ins.date][ins.id]) return;
  S.log[ins.date][nt.id] = 1;        // 旧的完成记录挪到新任务名下
});
```

同一时期大概还陆续加了：截止任务的倒计时标签（今天 / 明天 / 还有 N 天）、文件夹筛选、优先级分组、日历页的月视图。**具体是哪个版本加的，已经查不到了** —— 那时还没有写版本说明的习惯，这也是后来每一版都追加说明的原因。

## 这一段留下的三个教训

1. **字符串硬编码**：中文直接写在模板里，做英文时全部重抽了一遍。教训是「文案从第一行就该走字典」，哪怕当时只有一种语言。
2. **每周生成实例**：任务记录由「时间规则」派生出来，看着直观，一旦要改规则就得迁移历史数据。后来所有周期任务都改成「一条记录 + 规则」，靠规则实时算今天是第几轮。
3. **不留记录**：v1.5 之前的东西现在只能靠代码反推。从 v1.9 开始每一版都写清楚改了什么、为什么，这个习惯就是从这次「想不起来」开始的。

# 第一阶段 · 任务模型（v1.5 – v1.8）

## v1.5.0 任务类型合并成三类

**为什么**：原来是四种（固定 / 普通 / 按周 / 截止），用户得记四个名字，还要判断自己这件事属于哪种。

**改成**：三大类，周期变成任务的一个属性：

| 大类 | 里面包含 |
|---|---|
| 周期任务 | 每天、每周一次、每月一次、以及按星期几重复的老任务 |
| 普通任务 | 一次性，有时间或没时间 |
| 截止任务 | 只设截止日期，之前做完就行 |

新建时只选「重复：不重复 / 每天 / 每周 / 每月」，不用记类型名。

**顺带定的规则**：每周 / 每月任务一律不占「今日计划精力」（和截止任务一样）；今天勾掉，本周期内不再出现，到下一个周期自动恢复成未完成。

**怎么确认的**：用三个任务（跑 3km 每周、720 分每月、背单词每天）手动跑了一遍时间线 —— 今天都在；勾掉跑 3km 后当天消失、明天也不出现；下周一自己回来；720 分下月 1 号回来。

## v1.5.2 周期任务分组

**为什么**：周期任务一多，靠卡片副标题判断「这条是每天还是每周」太累。

**改成**：标题右侧直接显示分布 `每天 3 · 每周 2 · 每月 2`；组内按每天 / 每周 / 每月分三小节，左侧彩色竖条区分（绿=每天、蓝=每周、琥珀=每月）；只有一类时自动不显示小节，少一层嵌套。

## v1.6.0 周期任务规则定型

| 选择 | 还要选什么 | 显示规则 |
|---|---|---|
| 每天 | 不用选 | 每天都出现，勾掉当天消失，第二天回来 |
| 每周 | 周几（可多选，也可不选） | 选了周三：周一二不出现，周三起出现，做完本周期消失 |
| 每月 | 几号（1–31，单选） | 选了 20 号：20 号前不出现，20 号起出现，做完本月消失 |

不选周几 / 几号 = 不限日子，这一周期内每天都列着，做完就消失（「每周跑 3 公里」就是这种）。

**注意**：这一版周期任务还不进时间轴 —— 选了重复会自动把任务切成「无时间」。

## v1.7.0 带时间的周期任务

**为什么**：v1.6 的规则让「每周四 18:40 街舞培训」这种带固定时间的周期任务没法用。

**改成**：同一个任务可以既是周期、又有具体时段。选了重复以后日期行自动隐藏（哪天由规则决定），开始时间和时长照常填；不想要时间就打开「无时间」开关退回列表。

带时间的周期任务会自动登记到点提醒；精力按当天是否真的排了来算，不带时间的不算。

## v1.8.0 任务页成型

- 周期任务永远留在清单里：今天勾掉，任务页照样能看到（带删除线表示今天这份已完成），明天变回待办
- 普通任务按优先级分四组（紧急/高/中/低）、周期任务按每天/每周/每月分小节，点标题收起，折叠状态记住
- 筛选说明改成直白的话：「周期任务：每天 / 每周 / 每月」「截止任务：只设截止时间，截止时间之前完成即可」

## v1.8.2 四个小改进

- **笔记页有了保存按钮**（顶栏最右，绿色），点一下保存不退出
- **日历每天按状态上色**：日期圆圈填实色，灰=摆烂、绿=轻松/还行、橙=有点鸭梨、粉=累趴；只看今天及以前，未来不上色，日历底部有图例

## v1.8.4 卡片编辑与周期任务修正

- 三个页面的卡片，垃圾桶旁边加了铅笔按钮。点铅笔才编辑，点卡片别处不再误触。归档页不加
- 带具体时间的周期任务左侧加蓝色竖条，一眼和普通周期任务区分
- **修「周三显示周四任务」**：带时间的周期任务只在设定的那天出现
- 任务页补全时间信息：「1 小时 · 社团」→「每周 周四 · 18:40 · 1 小时」
- 任务页新增「全部任务」筛选，三类混排按优先级排

## v1.8.5 周期任务统一 + 归档可删

**为什么**：老「按星期排」的任务每周会生成一条独立记录，任务页里「书协培训」重复出现好几条。

**改成**：升级后第一次打开自动合并成一条「每周 周二 18:40 书协培训」，历史完成记录一并搬过去。每条周期任务的颜色各不相同（左侧竖条），今天 / 日程 / 任务三页一致。

归档页每张卡片右边加垃圾桶，可单条删，删前确认。

## v1.8.7 打勾统一在今天页

- 只有「今天」页的卡片能打勾，日程页和任务页的勾选框移除（避免误判）
- 日程页时间轴模式只显示时间点，不再在下面重复堆卡片
- 日程页列表模式显示这一天全部任务（周期 / 普通 / 截止三组）

## v1.8.8 补记 / 折叠 / 删除

- 日程列表模式的「普通任务」也能折叠了

## v1.8.9 常见疑问

今天页右上角（齿轮左边）加了问号按钮，8 组 35 条：精力怎么算 / 任务与周期 / 打勾与记录 / 提醒 / 数据 / 界面。

**这一版定下了一个模式**：所有「怎么用」的说明都进这里，界面本身不再堆解释文字。后面 v1.9.43 的设置页瘦身、v1.9.48 的小组件说明，都是这个思路的延续。

## v1.8.10 完成率改成实时算

**为什么**：以前用的是打开 App 那一刻的快照，没开过的日子就没有记录（柱子显示「–」），做完任务也不一定及时更新。

**改成**：`完成率 = 那天做完的 ÷ 那天安排的事`，每天现算。

分母包含：每天任务、那天该出现的每周/每月任务、日期落在那天的普通任务、当天的截止任务。

**关键细节**：做完就从列表消失的周期任务，依然算在当天分母里 —— 否则做完反而把分母变小，数字会偏高。没打开过 App 的日子也能算出真实值。

## v1.8.11 完成情况看的是选中那天

以前不管看哪天，详情面板都只显示今天的数字。改成跟着选中的日期走。

# 第二阶段 · 课表与外壳（v1.9.0 – v1.9.36）

## v1.9.0 课表（这一版是整个 App 的转折点）

**为什么**：日程应用不知道你什么时候有课，排出来的时间就是假的。

**怎么做的**：课程直接画在日程页的时间轴上，和任务同屏 —— 左上角标节次、虚线浅底。课程是背景，任务是你要做的事，一眼分开。

**课程不算任务**：不能打勾、不占精力、不进任务页、不影响完成率。

三步用起来：

1. 设置 → 课表 → 导入课表：选教务系统导出的 Excel（要含「上课明细」那张表），解析出预览，确认无误再导入。没有 Excel 可以先把 PDF 交给 AI 转一下
2. 设置 → 课表 → 开学第一周：填第 1 周周一的日期（如 2026-09-07），填了才算得出「今天是第几周」
3. 设置 → 课表 → 节次时间：默认是广西大学作息，其他学校自己改，留空表示那节不排课

**调课**：点时间轴上的课程块 →「停这一次」或「改时间/地点」，只影响那一天。

## v1.9.7 / v1.9.8 主题、点击判定、FAQ

- 右上角改成太阳 / 月亮切换，切换时两个图标交叉旋转淡入淡出，底色和文字色一起渐变
- **时间轴点卡片**：以前要「按住不动」才打得开，是判定机制的问题。改成松手走标准点击，拖拽过才忽略
- 常见疑问补两组共 9 条（课表 5 条、时间轴 4 条），总数到 35 条；顶部加搜索框，边打边过滤，搜到自动滚到第一条
- 右下角圆形 ↑ 按钮：往下滑就出现，点一下回到最上面
- **新用户使用说明**：首次打开自动生成一条「使用说明」笔记，八小节

## v1.9.9 切到时间轴停在最上面

以前从「列表」切回「时间轴」会自动滚到当天第一个任务（下午有事就跳到下午），改成一律停在「一天开始」那个点。

## v1.9.10 时间轴记住上次位置

按日期分别记住滚动位置：今天停在 20:00，切走再回来还是 20:00。

顺带修掉一个怪现象：以前停在最上头时切出去再进来会自己跑到下面（旧逻辑会去找「屏幕里有没有任务块」，找不到就滚到第一个任务）；现在不找任务了，只看历史位置。

## v1.9.12 时间轴左侧时间不再叠字

**问题**：两个安排紧挨着时（07:50 结束、08:00 开始），边界时间只有 11px 间距，字压在一起。

**改法**：挨太近的一组时间上下让开，间距统一撑到 17px，各自仍贴着自己块的上/下沿；让开时这组时间缩一号字（11.5 → 9.5px）；整点刻度如果正好和块边时间撞上就自动隐藏；很短的小块（十几分钟）只标开始时间。

## v1.9.13 左侧刻度回归纯刻度，起止时间挪进卡片

- 最左列只有整点刻度，不再显示块起止时间，彻底不会有叠字
- 每张卡片最左端显示这件事的时间：开始在上、结束在下，分别贴着卡片上/下沿，中间一条淡竖线分隔
- 卡片太矮（< 50px，约 45 分钟）只显示开始时间，时长写右边
- 并排的窄卡片时间列会缩窄、字号小一号

## v1.9.14 周期任务在任务页不再被划掉

**问题**：周期任务的「完成」只属于当前这一轮，但任务页套用了普通任务的完成样式，一划掉看着像永久做完了。

**改法**：标题不划线不变灰，右边挂小绿标「今天已完成 / 本周已完成 / 本月已完成」，下一轮开始标记自己消失。顺带修掉周期任务被归档的问题。

## v1.9.15 / v1.9.16 同步说明与隐藏

## v1.9.39 修「提醒不准时 / 打开 App 才响」

**现象**：任务 9:30、提前 10 分钟提醒，人一直没动 App，9:21 打开才收到。

**两个原因**：

1. **精确闹钟权限没拿到**。Android 14 起，`SCHEDULE_EXACT_ALARM` 对 targetSdk ≥ 33 的新装应用默认拒绝。没有它系统只给「不精确闹钟」—— 可以在合适的时候才投递，待机、省电模式下拖几十分钟很常见，直到设备被唤醒（你打开 App）才一起发出来。
   **修法**：清单里加 `USE_EXACT_ALARM`（Android 13 起这类应用安装即授予，不需要用户点）。

2. **App 开着的时候没走系统闹钟**。前台检查器只在「提醒时间的 3 分钟内」补发，超过就当错过了。窗口放宽到 15 分钟，闹钟万一没响，打开 App 也能看到。

**顺手做的**：
- 登记范围从 3 天扩到 7 天
- 设置 → 提醒新增「闹钟精度」一行，显示「精确 / 不精确 · 点此开启」
- 新增「30 秒后叫醒我（锁屏也能测）」—— 真走系统闹钟，锁屏 30 秒后该响
- 闹钟失败时不再把待取消列表清空

## v1.9.41 找到「测试通知点了没反应」的真正原因

**不是权限问题，是一个字母打错了。**

按钮在页面里的 id 是 `sTestNoti`，JS 里绑的是 `#sTestNotify`（末尾多一个 y）。查询不到元素，`if(tnb)` 直接跳过 —— **这个按钮从头到尾就没绑上任何东西**，所以点了连 toast 都没有。

这也解释了为什么 30 秒闹钟能响、这条不能：闹钟走的是完全不同的链路（AlarmManager → 广播 → 通知）。

**修法**：改 id，并且给打包流程加了一道检查 —— `check_ids.py`，JS 里绑定的 `#id` 如果在 HTML 里找不到，打包时报 `missing ids: [...]`。这个脚本现在是 `build_apk.sh` 的第 0 步。

**这一版还会看到的变化**：

## v1.9.57 找到真凶：尺寸读错了

**为什么之前怎么调都不对**

画布尺寸一直用 `OPTION_APPWIDGET_MIN_HEIGHT` 读。**vivo 在拉大组件时只更新 MAX，MIN 还停在初始值（300dp）**。于是按 300dp 画好的图被 fitXY 硬拉到 420dp 显示 —— 纵向拉伸 1.4 倍，卡片变细长、字变形、4×6 里第四行内容根本出不来。

诊断时看到过 `1088×2000` 这种离谱的尺寸（取 `max(min,max)` 之后），说明各家 launcher 的上报值完全不可信。

**这一版的做法**：不再猜绝对尺寸，改按**宽高比**判定 4×4 / 4×5 / 4×6（比例不受绝对值影响），每种用固定画布：

| 档位 | 画布 | 每格 |
|---|---|---|
| 4×4 | 250×300dp | 课名 + 地点 |
| 4×5 | 250×370dp | 课名 + 地点 + 节次 |
| 4×6 | 250×440dp | 课名 + 地点 + 节次 + 开始时间 |

画布按 1.7 倍密度渲染，被桌面缩放后不糊。卡片高度封顶在列宽的 2.1 倍。

**顺带**：设置里点「组件状态」能弹出 `宽x高 比例 → 档位`，是桌面实际报上来的值，排查全靠它。

## v1.9.59 「4×5 是假的」

**现象**：添加 4×5 组件，占的格子跟 4×4 一样。

# 附录 A · 构建链路

不用 Gradle，手写脚本。一条命令出包：

```
aapt2 compile --dir res -o res.zip
aapt2 link -o app.unsigned.apk -I $PLATFORM --manifest AndroidManifest.xml \
    -R res.zip --java gen -A assets --min-sdk-version 21 --target-sdk-version 33
javac -encoding UTF-8 -source 8 -target 8 -bootclasspath $PLATFORM -d classes \
    gen/com/liu/dailycat/R.java src/com/liu/dailycat/*.java
d8 --lib $PLATFORM --min-api 21 --output dex classes/com/liu/dailycat/*.class
# 把 classes.dex 塞进 apk
zipalign -f 4 app.unsigned.apk app.aligned.apk
apksigner sign --ks $KS --ks-pass pass:$KS_PASS --out Schedule.apk app.aligned.apk
```

**1. 补丁写对了 ≠ 生效**
出现过两次「assert 通过、脚本打印 ok，文件却没变」：
- 同一个 Python 脚本里先改了 `s`，后面又 `s = io.open(P).read()` 重读一遍，把前面的修改冲掉
- 改完忘了 `cp index.html app-src/assets/www/`，打出来的包还是旧的

现在固定流程：改 → grep 确认落盘 → 同步 assets → `check_ids.py` → 构建 → 报版本号。

**2. 大文件不能用 file_edit**
`index.html` 450KB，用 file_edit 会丢内容、错位，或者报成功但实际没改。一律改成「写 Python 脚本做精确字符串替换，每处 `assert s.count(o)==1`」，最后 `node --check` 验证语法。

**3. 视觉问题必须真渲染**
不靠脑补。组件用 `preview_widget2.py`（PIL 按真实 dp 复刻绘制逻辑），界面用 Chromium + Playwright 截图再局部放大看。`selftest_widget.py` 把「尺寸取值 → 判档 → 行高 → 内容分级」打成表格。

**4. 窄屏没测过等于没测**
v1.9.18–1.9.21 那四版返工，根因是一直在 800 宽视口里测，`.app` 有 `max-width:760` 兜着。之后所有布局都按 320 / 360 / 390 三个宽度各量一遍。

**5. 有些问题不是代码问题**
- 翻周按钮点不动 → launcher 不给子控件发点击
- 4×5 变 4×4 → launcher 用 `minHeight ÷ 单格高` 取整
- 读到 300dp 实际 420dp → launcher 只更新 MAX

遇到这类，第一件事是把平台给的原始值打印出来，而不是先改代码。

**6. 措辞要经得起时间**
启动页从「不联网」改成「单机运行」，是因为下一版就要加更新检查。写在界面上的承诺，等它变成假的再改，比一开始就写对更伤信任。
